# 04 - 真机移植指南（树莓派 + I2C 温湿度传感器）

> 本项目在 QEMU + i2c-stub 上跑通了全链路。换到真实硬件时，**驱动框架完全不用改**，
> 只改"数据从哪来"和"数据怎么解析"两件事。下面是完整清单。

---

## 一、硬件清单

| 物品 | 推荐型号 | 价格 | 说明 |
|------|---------|------|------|
| ARM 开发板 | 树莓派 4B / 5，或 Zero 2 W | ¥200–400 | 官方系统自带 I2C，设备树完善 |
| I2C 温湿度传感器 | **SHT30 / SHT31**（模块板） | ¥10–30 | 3.3V 供电，I2C 地址 0x44/0x45 |
| 备选传感器 | HTU21D(0x40) / DHT20(0x38) / AHT20 | ¥5–20 | 都是 I2C，改动点类似 |
| 杜邦线 | 母对母 4 根 | ¥5 | VCC/GND/SDA/SCL |
| （可选）ALERT 中断线 | 1 根 | — | 接 SHT30 的 ALERT 引脚到 GPIO |

> 为什么推荐 SHT30：命令字简单、精度好、模块板自带上拉电阻和电平转换，接线最省心。

## 二、接线（树莓派 40pin）

| 传感器 | 树莓派物理引脚 | 说明 |
|--------|---------------|------|
| VCC | 1 或 17（3.3V） | **不要接 5V** |
| GND | 6 / 9 / 14 / 20 / 25 / 30 / 34 / 39 | 任意 GND |
| SDA | 3（GPIO2，i2c-1 SDA） | 板载 1.8k 上拉 |
| SCL | 5（GPIO3，i2c-1 SCL） | |
| ALERT（可选） | 例如 7（GPIO4） | 接进中断用 |

## 四、设备树改动（两条路）

### 路线 A：最小改动（推荐先用这条跑通）

驱动保持 `platform_driver`，只把 `i2c-bus` 从 0 改成 1：

```dts
/* 追加到 /boot/firmware/config.txt 不行 —— 这是 dts，需用 overlay */
/ {
    sensor_char: sensor-char {
        compatible = "lucien,sensor-char";
        i2c-bus = <0x01>;          /* ★ i2c-stub 的 0 -> 树莓派的 1 */
        sensor-addr = <0x44>;      /* ★ 0x48 -> SHT30 的 0x44 */
        poll-interval-ms = <1000>;
        status = "okay";
    };
};
```

编译并启用 overlay：
```bash
# 在开发机上交叉编译 dtbo
dtc -@ -I dts -O dtb -o sensor-char.dtbo sensor-char-overlay.dts
scp sensor-char.dtbo pi@raspberrypi:/boot/firmware/overlays/
# 树莓派上
echo "dtoverlay=sensor-char" | sudo tee -a /boot/firmware/config.txt
sudo reboot
```
> 更简单粗暴的方式：如果不想做 overlay，可以在加载模块后用
> `echo "sensor_demo 0x44" > /sys/bus/i2c/devices/i2c-1/new_device` 手工实例化，
> 但那就失去了"设备树解耦"的意义，只适合临时验证。

### 路线 B：规范写法（传感器挂在 I2C 控制器下）

```dts
&i2c1 {
    status = "okay";
    clock-frequency = <100000>;

    sensor@44 {
        compatible = "lucien,sensor-char";
        reg = <0x44>;                       /* I2C 从地址写在 reg 里 */
        poll-interval-ms = <1000>;
        interrupt-parent = <&gpio>;
        interrupts = <4 IRQ_TYPE_EDGE_FALLING>;   /* 可选：ALERT 接 GPIO4 */
    };
};
```
对应驱动改动（probe 里）：
```c
/* 传感器节点是 i2c 控制器的子节点，从父节点拿 adapter */
struct device_node *i2c_np = of_get_parent(dev->of_node);
sd->adapter = of_find_i2c_adapter_by_node(i2c_np);
of_node_put(i2c_np);
/* 地址直接从 reg 读，不用自定义 sensor-addr 属性 */
of_property_read_u32(dev->of_node, "reg", &addr);
```

## 五、驱动改动清单（共 3 处）

### 改动 1：I2C 地址/总线（已由设备树解决）
无需改代码（路线 A）或改 adapter 获取方式（路线 B）。

### 改动 2：传感器读取函数（`sensor_irq_thread`）

SHT30 的协议不是简单寄存器读，要"发命令 + 读 6 字节 + CRC 校验"：

```c
/* 替换 sensor_char.c 里的 i2c_smbus_read_word_data(...) */
u8 cmd[2]  = { 0x2C, 0x06 };     /* 高重复性测量，无时钟拉伸 */
u8 buf[6];
struct i2c_msg msgs[2] = {
    { .addr = sd->client->addr, .flags = 0,        .len = 2, .buf = cmd  },
    { .addr = sd->client->addr, .flags = I2C_M_RD, .len = 6, .buf = buf  },
};
ret = i2c_transfer(sd->client->adapter, msgs, 2);
if (ret != 2) { sd->i2c_errors++; return IRQ_HANDLED; }

/* CRC 校验（SHT30 用 CRC-8, 多项式 0x31） */
if (crc8(buf, 2) != buf[2] || crc8(buf + 3, 2) != buf[5]) {
    sd->i2c_errors++;
    return IRQ_HANDLED;
}

u16 raw_t = (buf[0] << 8) | buf[1];
u16 raw_h = (buf[3] << 8) | buf[4];

/* ★ 解析公式（替换 RAW_TO_MILLI） */
int temp_milli = -45000 + (s64)175000 * raw_t / 65535;   /* -45 + 175*S/65535 °C */
int humi_milli = 100000 * (s64)raw_h / 65535;            /* 0-100 %RH */
```

```c
/* CRC-8（SHT3x 数据手册给出） */
static u8 crc8(const u8 *data, int len)
{
    u8 crc = 0xFF;
    for (int i = 0; i < len; i++) {
        crc ^= data[i];
        for (int b = 0; b < 8; b++)
            crc = (crc & 0x80) ? (crc << 1) ^ 0x31 : (crc << 1);
    }
    return crc;
}
```

### 改动 3：中断源（真机接 ALERT 引脚）

```c
/* 删掉整个虚拟中断域（sensor_virt_irq_chip / sensor_irq_domain_ops 以及相关代码） */
/* 改为从设备树取硬件中断号 */
sd->virq = platform_get_irq(pdev, 0);
if (sd->virq < 0)
    dev_warn(dev, "no ALERT irq in DT, fall back to polling timer\n");
else
    request_threaded_irq(sd->virq, sensor_irq_hard, sensor_irq_thread,
                         IRQF_TRIGGER_FALLING | IRQF_ONESHOT, DRV_NAME, sd);
```
> `IRQF_ONESHOT` 对线程化中断很重要：保证下半部执行完之前不会再次触发。
> 不接 ALERT 也可以：保留 hrtimer 轮询（本项目现有代码），只是多耗一点功耗。

## 六、编译与加载

### 方式 1：树莓派上直接编译（最省事）

```bash
# 把项目拷到树莓派
scp -r driver/ pi@raspberrypi:~/sensor-driver/
ssh pi@raspberrypi
cd ~/sensor-driver
make                       # KDIR 默认 /lib/modules/$(uname -r)/build
sudo insmod sensor_char.ko
dmesg | tail -6
```

### 方式 2：在开发机上交叉编译（项目要求的"交叉编译工具链"）

```bash
# 拿到树莓派内核源码/headers 后
make ARCH=arm64 CROSS_COMPILE=aarch64-linux-gnu- \
     -C /path/to/raspberrypi-kernel M=$PWD modules
```
> 注意：**交叉编译的模块必须与树莓派内核版本完全一致**，否则 `invalid module format`。
> 用 `modinfo sensor_char.ko | grep vermagic` 与 `uname -r` 对比验证。

### 加载与验证

```bash
sudo insmod sensor_char.ko
dmesg | tail                      # 看 probe 日志（DT 参数、i2c client、irq）
ls -l /dev/sensor0                # 字符设备节点
cat /dev/sensor0                  # 阻塞读取，每秒一行温度
./sensor_test                     # 用户态完整测试
sudo rmmod sensor_char
```

## 八、常见真机问题

| 现象 | 原因 | 解决 |
|------|------|------|
| `i2cdetect` 看不到设备 | 接线错 / 没启用 I2C / 供电错 | 检查 SDA/SCL 是否接反、3.3V、`raspi-config` |
| probe 一直 `-EPROBE_DEFER` | I2C 控制器还没就绪 | 确认 `dtoverlay=i2c1`、驱动是模块时检查加载顺序 |
| `-EREMOTEIO` | 传感器 NAK（地址错/命令错） | `i2cget -y 1 0x44 0x00 w` 交叉验证 |
| 温度值明显不对 | 解析公式或字节序错 | `dev_dbg` 打印 `raw`，用数据手册公式手算 |
| 中断不触发 | ALERT 引脚极性/上拉配置错 | 改 `IRQ_TYPE_EDGE_FALLING`→`RISING`，或先用轮询模式 |
| `invalid module format` | 模块与内核版本不一致 | 用树莓派上的 headers 重编 |
