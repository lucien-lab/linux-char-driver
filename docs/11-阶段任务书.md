# 阶段任务书（六个阶段的接口契约）

> 本文件规定每个阶段**必须实现什么、接口叫什么名字、用什么验证**。
> 命名与路径是契约：后续阶段与文档都会引用它们，不要随意改名。
> 未写明的实现细节由实现者自行决定，但必须遵守 `docs/10-开发与验证守则.md`。

## 通用要求（每阶段都适用）

- 每阶段结束必须：阶段测试全绿 + `smoke` 回归全绿 + 三份文档（`docs/impl`、`docs/kb`、`docs/verify`）。
- 已有 ioctl 命令号与结构体字段**只能追加，不能改动**（ABI 兼容）。
- 每阶段的实现要在现有代码基础上做**最小必要改动**，不要把无关代码重排（便于 review 与 diff）。

## 阶段 01：四种 IO 模型（阻塞 / 非阻塞 / poll·epoll / fasync·SIGIO）

**目标**：把 `sensor_char.c` 的字符设备接口从"只有阻塞 read"补全为教科书级的四种 IO 模型，
并让"新样本"语义在**每个 open 的文件描述符上独立**（这是 poll 正确性的前提）。

### 接口契约

1. 新增 per-open 上下文：

```c
struct sensor_file {
	struct sensor_dev *sd;
	u32 last_seq;		/* 本 fd 已经消费到的样本序号 */
};
```
   - `sensor_open()` 用 `kzalloc` 分配它，`file->private_data = sf`；
   - `sensor_release()` 里 `kfree`（并调用 `sensor_fasync(-1, filp, 0)` 摘除异步通知）。

2. 数据可用判定统一为一个函数（read/poll 共用，避免语义漂移）：

```c
static bool sensor_has_new_sample(struct sensor_file *sf);   /* latest.seq != sf->last_seq */
```

3. `read()` 语义：
   - 有新样本 → 返回（并更新 `sf->last_seq`）；
   - 无新样本且 `O_NONBLOCK` → `-EAGAIN`；
   - 无新样本且阻塞 → 在 `sd->wq` 上等待（保留原有 2 秒超时 → `-ETIMEDOUT`）。
   - **注意**：现在的实现用"进入 read 时的 seq"做基准，必须在阶段 01 改成基于 `sf->last_seq`，
     否则同一个 fd 连续 read 会拿到重复样本。

4. `poll`：

```c
static __poll_t sensor_poll(struct file *filp, poll_table *wait);
```
   - 先 `poll_wait(filp, &sd->wq, wait)`，再判断 `sensor_has_new_sample()`，
     有则返回 `EPOLLIN | EPOLLRDNORM`，否则 0；
   - 必须**电平触发语义正确**：同一个样本被 read 消费后，poll 不能再报 EPOLLIN
     （用"3 秒内 epoll_wait 唤醒次数"来验证，见测试脚本）。

5. `fasync`：

```c
static int sensor_fasync(int fd, struct file *filp, int on);   /* fasync_helper */
```
   - `struct sensor_dev` 增加 `struct fasync_struct *fasync;`
   - 在**线程化中断下半部更新完 `latest` 并 `wake_up_interruptible(&sd->wq)` 之后**，
     调用 `kill_fasync(&sd->fasync, SIGIO, POLL_IN)`；
   - `file_operations` 增加 `.fasync = sensor_fasync`。
   - 需要 `#include <linux/poll.h>`（`poll_wait`/`kill_fasync` 都在其中）。

6. `file_operations` 最终形态需包含：`.open .release .read .write .unlocked_ioctl .poll .fasync .llseek`。

### 用户态测试程序

`user/io_models_test.c`（会被编译为 `/bin/io_models_test`），要求：

1. **阻塞 read**：以默认（阻塞）方式 open，read 一次成功；
2. **非阻塞 read**：`O_NONBLOCK` open，连续 read 直到出现 `EAGAIN`（记录尝试次数）；
3. **epoll**：把 fd 加入 epoll，`epoll_wait` 超时 3000ms；统计 3 秒内被唤醒次数与是否读到数据；
4. **SIGIO**：`fcntl(F_SETOWN, getpid())` + 安装 SIGIO handler + `fcntl(F_SETFL, O_ASYNC)`，
   用 `sigtimedwait` 或 handler 计数，最多等 3 秒，统计收到信号次数；
   结束时必须 `fcntl(F_SETFL, ...&~O_ASYNC)` 清理。

输出格式（脚本按行 grep，必须逐字一致）：`[IO] <键>=<值>`，至少包含：

```
[IO] blocking_read=ok
[IO] nonblock_eagain=<次数>
[IO] epoll_wait_ok=1
[IO] epoll_wakeups=<3秒内唤醒次数>
[IO] sigio_count=<信号次数>
[IO] OVERALL=PASS|FAIL
```

退出码：全部通过 0，否则非 0。

| SIGIO 异步通知到达 | `sigio_count` ≥ 1 | fasync 通路 |
| 程序整体结论 | `[IO] OVERALL=PASS` | —— |
| 该内核支持 ftrace 过滤 kill_fasync | `FT_OK = 1` | 防止静默少一项仍显示全绿 |
| ftrace 捕获到 kill_fasync | `FT_KF` ≥ 1 | 异步通知确实由下半部触发 |
| 无内核告警 | dmesg 无 `WARNING:`/`Call trace:` | —— |

## 阶段 02：虚拟 I2C 控制器 + 标准 i2c_driver + regmap + 设备树 i2c 子节点匹配

**目标**：把"platform_driver + `i2c_get_adapter()` 手工创建 client + 直接 `i2c_smbus_*`"
升级为**产品级形态**：总线控制器（真实驱动力）由设备树描述 → i2c 核心自动枚举子设备 →
驱动以 `i2c_driver` 注册 → 寄存器访问走 `regmap`。

**为什么必须自己写一个虚拟 I2C 控制器**：QEMU 的 `virt` 机器没有 I2C 控制器，
`i2c-stub` 创建的适配器没有设备树节点，因此子设备无法从设备树枚举，
也就无法真正验证"设备树 + i2c_driver 匹配"。

### 接口契约

1. 新增 `driver/virt_i2c.c`（编译为 `virt_i2c.ko`）：

   - `platform_driver`，`of_match_table` 匹配 `compatible = "lucien,virt-i2c"`；
   - 注册 `struct i2c_adapter`，**必须设置 `adapter.of_node = pdev->dev.of_node`**
     （否则 i2c 核心不会从设备树枚举子节点）；
   - 实现 `i2c_algorithm.smbus_xfer`（`regmap` 用 8 位寄存器 + 16 位数据时会走 SMBus word 访问），
     以及 `functionality` 返回 `I2C_FUNC_SMBUS_BYTE_DATA | I2C_FUNC_SMBUS_WORD_DATA`；
   - 模拟一颗温度传感器芯片的寄存器空间（tmp105 语义）：
     - `0x00` 温度寄存器（16 位，高位为符号位，LSB = 1/16 ℃）；
     - `0x01` 湿度寄存器（可选，16 位，0.01 %RH）；
     - `0x02` 配置寄存器；
     - 温度值按内部计数做**确定性漂移**（不要用随机数，否则测试无法复现）；
   - 提供**故障注入**接口（阶段 04 会用到，此处先实现）：
     `/sys/kernel/debug/virt_i2c/inject_error`（WO，写 N 表示接下来 N 次传输返回 `-EIO`）、
     `/sys/kernel/debug/virt_i2c/stats`（RO，输出 `transfers=N errors=M injected_left=K`）。

2. `driver/sensor_char.c` 重构：

   - 由 `platform_driver` 改为 **`i2c_driver`**：

```c
static int  sensor_probe(struct i2c_client *client);
static void sensor_remove(struct i2c_client *client);
static const struct i2c_device_id sensor_id[] = { { "sensor_char", 0 }, {} };
static const struct of_device_id sensor_of_match[] = { { .compatible = "lucien,sensor-char" }, {} };
```
   - 寄存器访问改为 `regmap`：

```c
static const struct regmap_config sensor_regmap_cfg = {
	.reg_bits = 8, .val_bits = 16, .max_register = 0x02,
	/* 必须显式声明：不写时 regmap_get_val_endian() 默认返回 BIG，
	 * 会选 regmap_smbus_word_swapped 后端做 swab16()，把温度读成乱码
	 * （实测 25.0 ℃ 被读成 2096 ℃ 量级）。SMBus word 本身是低字节在前。 */
	.val_format_endian = REGMAP_ENDIAN_LITTLE,
};
sd->regmap = devm_regmap_init_i2c(client, &sensor_regmap_cfg);
/* 读温度：regmap_read(sd->regmap, SENSOR_REG_TEMP, &raw) */
```
     `i2c_errors` 计数在 `regmap_read` 失败时累加。
   - 保留（不要丢）：字符设备注册、`waitqueue`、四种 IO 模型、`poll/fasync`、
     自建虚拟中断控制器（`irq_chip + irq_domain`）+ `request_threaded_irq` 上下半部分离，
     以及 `poll-interval-ms` 设备树属性解析。
     - 中断部分可以有两种做法，任选其一并在文档说明理由：
       (a) 保留在 `sensor_char.c`（注释说明真机上这是传感器 DRDY 引脚）；
       (b) 迁移到 `virt_i2c.c`（更贴近硬件事实：中断线由"板级/芯片"提供）。
   - **删除** `i2c_get_adapter()` + `i2c_new_client_device()` 的手工实例化路径。

3. 设备树：`dts/sensor-node.dts.inc` 改为

```dts
	virt_i2c: virt-i2c {
		compatible = "lucien,virt-i2c";
		#address-cells = <0x01>;
		#size-cells = <0x00>;
		status = "okay";

		sensor0: sensor@48 {
			compatible = "lucien,sensor-char";
			reg = <0x48>;
			poll-interval-ms = <0x1f4>;
		};
	};
```
   （节点插入逻辑不变，仍由 `scripts/20-macos-gen-dtb.sh` 完成。）

4. `driver/modules.load` 改为：`virt_i2c.ko` → `sensor_char.ko`（不再需要 `i2c-stub`）。

## 阶段 03：kfifo 环形缓冲 + mmap 零拷贝 + 多进程并发

**目标**：解决"采样速率与读取速率失配"（现在的实现只缓存**一个**最新样本），
提供用户态零拷贝访问通道，并在多进程并发下验证无竞态。

### 接口契约

1. **kfifo 通道**（read() 的数据源）：
   - `struct sensor_dev` 增加 `struct kfifo ring;`（容量 64 个 `struct sensor_sample`），
     probe 时 `kfifo_alloc(&sd->ring, 64 * sizeof(struct sensor_sample), GFP_KERNEL)`；
   - 线程化中断下半部：`kfifo_put()` 入队新样本；队满时**丢弃新样本**并累加
     `sd->kfifo_dropped`（丢弃策略必须写进文档，说明为什么选它）；
   - `read()` 改为：从 kfifo 取一个（`kfifo_get`），无数据时按阶段 01 的语义等待/`-EAGAIN`。
     `sensor_has_new_sample()` 判定改为 `!kfifo_is_empty(&sd->ring)`。
   - `struct sensor_stats`（`driver/sensor_ioctl.h`）**追加**字段（保持 ABI 兼容）：
     `__u32 kfifo_dropped; __u32 ring_count;`

2. **mmap 零拷贝通道**：
   - 用 `__get_free_pages(GFP_KERNEL | __GFP_ZERO, 0)`（1 页）分配共享缓冲区，
     只读映射给用户态（`.mmap` 里用 `remap_pfn_range`，权限 `PAGE_READONLY`）；
   - 布局（固定，用户态按此解析）：

```c
#define SENSOR_SHM_MAGIC 0x53454E53	/* "SENS" */
struct sensor_shm {
	__u32 magic;			/* SENSOR_SHM_MAGIC */
	__u32 version;			/* 1 */
	__u32 count;			/* 有效样本数（<= 32） */
	__u32 write_idx;		/* 下一个写入位置 */
	__u32 seq;			/* 序号，偶数=一致，奇数=写入中（seqlock 约定） */
	__u32 reserved[3];
	struct sensor_sample samples[32];
};
```
   - **用户态可见的 seqlock 协议必须真的成立**（阶段 03 验证者发现初版是假实现：
     内核从不写 `shm->seq`，用户态重试逻辑是死代码）。正确做法是内核亲手维护这个可见序号，
     并给出显式屏障（`seqlock_t` 内部的 seqcount 用户态看不到，不能只靠它）：

```c
/* 写入方（线程化中断下半部）：seq 奇数=写入中，偶数=一致 */
spin_lock(&sd->shm_lock);                 /* 序列化多个写者 */
smp_wmb();                                /* 保证下面这行先于数据写可见 */
WRITE_ONCE(shm->seq, shm->seq + 1);       /* → 奇数 */
/* … 更新 header（count/write_idx）与 samples[] … */
smp_wmb();                                /* 保证数据写先于 seq 自增可见 */
WRITE_ONCE(shm->seq, shm->seq + 1);       /* → 偶数 */
spin_unlock(&sd->shm_lock);
```
     用户态用"读 seq（volatile）→ 奇数则重试 → 读数据 → 重读 seq → 变化或为奇数则重试"的方式读取；
     **配套检查必须能发现"内核不写 seq"这种错**（例如断言 `shm->seq` 在测试期间真的推进、",
     并在负控实验中确认删掉 seq 写入会 FAIL）。
   - 需要 `#include <linux/mm.h>`；`.mmap` 要检查映射长度（超过 1 页返回 `-EINVAL`）。

3. **多进程并发**：允许多个进程同时 open（当前已允许），
   per-open 状态（阶段 01 的 `struct sensor_file`）保证互不干扰。

### 用户态测试程序

- `user/ring_mmap_test.c`：
  1. `ioctl(GET_STATS)` 读初始计数；
  2. `ioctl(SET_INTERVAL, 10)` 把周期调到 10ms，然后 **3 秒不读**，
     再 `ioctl(GET_STATS)` 读 `kfifo_dropped`（应 > 0，证明溢出策略生效）；
  3. `mmap` 拿到共享区，按 seqlock 方式读 100 次，校验 `magic`/`version` 正确、
     `samples[i].seq` 单调不回退、撕裂重试次数有统计；
  4. 输出 `[RING] dropped=<n>`、`[RING] mmap_reads=100 mmap_retries=<n> mmap_invalid=<n>`、
     `[RING] OVERALL=PASS|FAIL`。
- `user/concurrency_test.c`：
  - `fork` 8 个子进程，每个 open 一次，循环 200 轮：read（非阻塞，取到就校验
    `temp_milli` 在 `[15000, 45000]` 区间）、`ioctl(GET_SAMPLE)`、mmap 读校验；
  - 子进程用退出码表达结果，父进程 `waitpid` 统计失败数；
  - 输出 `[CONC] children=8 failed=<n> invalid_samples=<n> i2c_errors=<n>`、
    `[CONC] OVERALL=PASS|FAIL`。

**集成负责人裁定（阶段 03 起生效）**：
1. 阶段 01 的 per-open `struct sensor_file` 在阶段 03 **正式退役**：共享 kfifo 语义下，
   多个 open 的文件描述符从同一个队列消费（各取各的样本），「消费后不再可读」由队列空来表达。
   阶段 01 的 16 项检查仍必须全绿（它们验证的是 IO 模型语义，不是 per-open 实现细节）。
2. QEMU 统一以 **`-smp 2`** 运行（`scripts/20/22` 已改）：单核下所有 SMP 竞态不可触发，
   「并发无竞态」的结论没有证据价值。
3. 关于「无竞态」的表述纪律：只有「多核 + 全局唯一性断言（+ 可选的 KCSAN）」都拿到证据，
   才允许在文档/简历里写「无竞态」；否则必须写成「冒烟级并发回归」，并说明局限。

## 阶段 04：sysfs 暴露设备参数 + debugfs 导出运行统计

**目标**：补上内核向用户空间暴露信息的两种标准接口，并用它们实现"不停机调参 + 现场观测 + 故障注入"。

### 接口契约

1. **sysfs**（挂在字符设备类设备上，即 `/sys/class/sensor_char/sensor0/`）：

| 文件 | 权限 | 语义 |
|---|---|---|
| `interval_ms` | RW | 采样周期，写入立即生效（改 hrtimer 周期），范围 1~60000，非法值返回 `-EINVAL` |
| `seq` | RO | 当前最新样本序号 |
| `i2c_errors` | RO | 累计 I2C 传输失败次数 |
| `ring_capacity` | RO | kfifo 容量（样本数） |

   实现用 `DEVICE_ATTR_RW`/`DEVICE_ATTR_RO` + `sysfs_create_group()`（remove 时 `sysfs_remove_group()`）。

2. **debugfs**：`/sys/kernel/debug/sensor_char/`

| 文件 | 权限 | 语义 |
|---|---|---|
| `stats` | RO | 一行多字段：`open=N read=N irq=N i2c_err=N interval=N dropped=N ring_count=N seq=N` |
| `ring` | RO | 环形缓冲状态与最近若干样本（至少打印 count/dropped 与最近 8 条 `seq/temp`） |
| `regs` | RO | 通过 regmap 实时读取传感器寄存器 0x00~0x02 并打印（证明 regmap 通路） |

   用 `debugfs_create_dir()` + `debugfs_create_file()`，remove 时 `debugfs_remove_recursive()`。

3. 与阶段 02 的故障注入配合：`virt_i2c` 的 `/sys/kernel/debug/virt_i2c/inject_error`
   写入 N 后，接下来 N 次传输返回 `-EIO`，驱动的 `i2c_errors` 应随之增长。

**集成负责人裁定（两条行为约定，均已由实现者落地）**：
1. **采样周期下限统一为 1ms**：原 `ioctl(SENSOR_IOC_SET_INTERVAL)` 下限是 10ms，与 sysfs 契约的 1ms 冲突
   （同一设置走不同入口结果不同，属于接口不一致）。现已抽成 `sensor_interval_valid()` + `sensor_apply_interval()`，
   两个入口统一为 `1~60000`。这是**放宽**（向后兼容）且没有任何既有测试依赖旧下限。
   副作用：用户态可把周期调到 1ms 使 kfifo 快速溢出，表现为 `dropped` 增长——这是阶段 03 定下的
   "丢新 + 计数" 预期行为，不是缺陷。
2. **debugfs 创建失败不是致命错误**：生产内核常不挂 debugfs，`debugfs_create_dir()` 会返回 `ERR_PTR(-ENODEV)`。
   处理方式为 `dev_warn` + 指针置 NULL，清理路径统一走 `debugfs_remove_recursive(NULL)`（该函数对 NULL 安全）。

### 阶段测试脚本 `tests/phases/04-sysfs-debugfs.sh`，至少包含

| 检查项 | 判定 |
|---|---|
| sysfs 属性齐全 | 四个属性文件都存在 |
| sysfs 可读 | `interval_ms`/`seq`/`i2c_errors`/`ring_capacity` 读出的都是数字 |
| sysfs 可写且立即生效 | 写 `interval_ms=100` 后用 `ioctl(GET_STATS)` 读到 100 |
| 非法值被拒绝 | 写 `interval_ms=0` 失败（shell 输出错误或值不变） |
| debugfs stats 完整 | 输出包含 `open=`、`irq=`、`i2c_err=`、`dropped=` |
| debugfs regs 可读寄存器 | 输出包含 `00:` 或 `0x00` 之类的寄存器行 |
| 故障注入生效 | 注入 3 次后 `i2c_errors` 增量 ≥ 3 |
| 注入后系统仍正常 | 注入结束后 `sensor_test` 仍退出码 0、无内核告警 |

## 阶段 05：IIO 子系统驱动（triggered buffer + hrtimer trigger）

**目标**：同一个虚拟传感器，再写一个**符合内核 IIO 子系统规范**的驱动，
与字符设备版并存；说清"什么时候该用子系统框架、什么时候该自己写 fops"。

### 接口契约

1. 新增 `driver/sensor_iio.c`（编译为 `sensor_iio.ko`），`i2c_driver` 形态，
   匹配 `compatible = "lucien,sensor-iio"`（设备树里再加一个子节点，
   例如 `sensor1: sensor@49`，用另一个从机地址避免与字符设备版抢同一设备）；
2. 通道定义：
   - `IIO_TEMP` → `in_temp_input`，单位毫摄氏度（`IIO_VAL_INT` 返回 m°C，
     需要 `iio_convert_raw_to_processed` 的等价换算，请写清换算与 scale）；
   - `IIO_HUMIDITYRELATIVE` → `in_humidityrelative_input`（可选，用湿度寄存器）；
3. `read_raw()`：通过 `regmap_read()` 取原始值 → 换算 → 返回；
4. 缓冲与触发：

```c
ret = devm_iio_triggered_buffer_setup(&client->dev, indio_dev,
				      NULL, sensor_iio_trigger_handler, NULL);
```
   触发源用内核标准的 **hrtimer software trigger**（`CONFIG_IIO_HRTIMER_TRIGGER=y`），
   通过 configfs 实例化：

```sh
# 1) 用 configfs 创建 hrtimer 软件触发器的实例（只创建实例）
mkdir /sys/kernel/config/iio/triggers/hrtimer/inst0
# 2) 采样频率 **不在 configfs 实例目录里**，而在创建出来的 trigger 设备上：
#    /sys/bus/iio/devices/triggerN/sampling_frequency
#    （阶段 05 实测：写 configfs 目录会得到误导性的 EACCES；
#      依据 drivers/iio/trigger/iio-trig-hrtimer.c 的 DEVICE_ATTR 定义）
echo 100 > /sys/bus/iio/devices/trigger0/sampling_frequency
# 3) trigger 的 name 就是 configfs 的实例名（实测为 inst0，不是 hrtimer）；
#    绑定时写的是这个名字：echo inst0 > /sys/bus/iio/devices/iio:deviceN/trigger/current_trigger
```
   然后 `echo <trigger_name> > /sys/bus/iio/devices/iio:deviceN/trigger/current_trigger`，
   再 `echo 1 > .../buffer/enable`；用户态读 `/dev/iio:deviceN` 得到扫描元素字节流。

5. `driver/modules.load` 或 `tests/phases/05-iio.sh.modules`：
   该阶段只加载 `virt_i2c.ko` + `sensor_iio.ko`（**不要加载 `sensor_char.ko`**，
   两个驱动会争抢同一 i2c 从设备）。

### 用户态测试程序

`user/iio_read_test.c`：打开 `/dev/iio:device0`，读若干次（每次 `scan_size` 字节），
解析 channel 0（温度）的 int 值，校验在合理区间（15000~45000 m°C），
输出 `[IIO] dev_reads=<n> temp_milli=<值> OVERALL=PASS|FAIL`。

### 阶段测试脚本 `tests/phases/05-iio.sh`，至少包含

| 检查项 | 判定 |
|---|---|
| IIO 设备注册 | `/sys/bus/iio/devices/iio:device0/name` 内容非空 |
| 通道存在 | `in_temp_input_raw` 或 `in_temp_input` 可读且数值在合理区间 |
| hrtimer trigger 实例化 | configfs 建实例后 `/sys/bus/iio/devices/trigger*/name` 出现 `hrtimer` |
| 缓冲可开启 | `buffer/enable` 写入 1 成功 |
| 触发绑定成功 | `trigger/current_trigger` 写入后回读一致 |
| 用户态能读到缓冲样本 | iio_read_test 输出 `OVERALL=PASS` 且读到 ≥ 3 个样本 |
| 无内核告警 | dmesg 无 `WARNING:`/`Call trace:` |

## 阶段 06：Runtime PM + KUnit

**目标**：补上嵌入式高频考点"Linux 电源管理"，并用内核单元测试覆盖纯逻辑函数。

### 接口契约

1. **Runtime PM**（在 `sensor_char.c`）：

```c
static int sensor_runtime_suspend(struct device *dev);   /* 停 hrtimer、禁止中断 */
static int sensor_runtime_resume(struct device *dev);    /* 恢复采样 */
static const struct dev_pm_ops sensor_pm_ops = {
	SET_RUNTIME_PM_OPS(sensor_runtime_suspend, sensor_runtime_resume, NULL)
};
```
   - probe 里 `pm_runtime_enable()` + `pm_runtime_set_autosuspend_delay(dev, 1000)` +
     `pm_runtime_use_autosuspend(dev)`；
   - `open()` 里 `pm_runtime_get_sync()`（或 `pm_runtime_resume_and_get()`），
     `release()` 里 `pm_runtime_mark_last_busy()` + `pm_runtime_put_autosuspend()`；
   - remove 里 `pm_runtime_disable()`；
   - `suspend` 时必须**停掉 hrtimer 并关中断**（否则设备无法真正进入低功耗），
     `resume` 时重新启动；两者都要打印日志便于验证。

**集成负责人裁定（阶段 06 实测后有两条偏离契约，均接受）**：

1. **`remove()` 里 `pm_runtime_disable()` 必须在停 hrtimer/关中断之前调用**（与契约原顺序相反）。
   理由：若先停 hrtimer 再 disable，两者之间存在窗口，内核可能回调 `runtime_resume()`
   把 hrtimer 重新 `hrtimer_start()` 回来，导致"停不掉"的竞态。实现已按此顺序并写进代码注释。
2. **阶段 04 测试脚本的必要适配**：阶段 06 引入 Runtime PM 后，"无人持有设备时自动挂起并停止采样"，
   于是阶段 04 的故障注入段（原设计靠周期性 I2C 读消耗注入次数）必须显式持有设备引用
   （`exec 3<>/dev/sensor0`），否则该段实际测到的是"挂起后不采样"。这属于行为变化导致的适配，
   **不是放宽检查**；阶段 04 的 42 项检查项一个都没减少。

2. **KUnit**：新增 `driver/sensor_calc.h` 放纯逻辑函数（`static inline`），
   驱动与该测试共用：

```c
static inline s32 sensor_raw_to_milli(u16 raw);              /* 12 位补码 -> 毫摄氏度 */
static inline bool sensor_interval_valid(unsigned long ms);  /* 1..60000 */
static inline u32 sensor_fifo_next(u32 idx, u32 cap);        /* 环形下标推进 */
```
   新增 `driver/sensor_kunit.c`（编译为 `sensor_kunit.ko`）用 `kunit_test_suite()` 写测试，
   覆盖：零点、正负边界（`raw=0x0000/0x7FF/0x800/0xFFF`）、非法周期、
   环形下标回绕；测试用例名要有意义（例如 `sensor_raw_to_milli_boundaries`）。

### 阶段测试脚本 `tests/phases/06-runtime-pm-kunit.sh`，至少包含

| 检查项 | 判定 |
|---|---|
| runtime PM 已启用 | `/sys/bus/i2c/devices/0-0048/power/control` 内容为 `auto` |
| 打开时保持活跃 | open 期间 `power/runtime_status` 为 `active` |
| 关闭后自动挂起 | 关闭并等待 > autosuspend 延迟后 `runtime_status` 变为 `suspended` |

> **集成负责人契约修正（阶段 06 实测）**：Runtime PM 的 sysfs 节点挂在**硬件设备**上
> （i2c client：`/sys/bus/i2c/devices/0-0048/power/`），**不是**字符设备类设备
